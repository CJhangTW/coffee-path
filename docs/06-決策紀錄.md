# 06｜架構與體驗決策紀錄（ADR）

| ID | 決策 | 原因 | 重新評估條件 |
|---|---|---|---|
| ADR-001 | Journey 為主要新手入口；Lab/Atlas 對熟手直接開放 | 新手需低負擔，熟手不能被迫重玩 | 用戶測試發現大量迷失 |
| ADR-002 | 豆點累積不消耗；收藏只記錄成就 | 不引入經濟系統複雜性及刷分問題 | 未來需要完整遊戲系統時再評估 |
| ADR-003 | 研究說明可藉進度展開，亦可手動解除限制 | 保留遊戲感且不知識封鎖 | 用戶測試認為開通過於繁瑣時更簡化 |
| ADR-004 | JSON 內容驅動 + domain 純函式 | 支援 100+ 條目擴展與 Codex 可維護性 | 資料確實增長到需要更嚴格版本管理 |
| ADR-005 | 原生 ESM、無建置工具、無框架 | 符合開源可讀、靜態部署與低運維 | 僅在明確獲開發者同意後變更 |
| ADR-006 | Three.js 只按需載入且有 2D fallback | 手機效能和無障礙優先 | 3D 原型證明足夠教學收益 |
| ADR-007 | 不做物理上精確的風味／TDS 模型 | 現有資料不足以支援精確預測 | 有可靠研究模型、校驗數據時獨立規格 |
| ADR-008 | 資料以 strict、derived、adapted、excluded 標記 | 保持三原料主題與真實文化描述 | 需要支持額外原料時另開產品線 |
| ADR-009 | 單站 `site/` 靜態資產，GitHub → Pages | 易於自託管與自訂網域 | 託管商政策重大變更 |
| ADR-010 | `location.hash` 導航 | 無伺服器 rewrite 設定、連結好分享 | SEO 要求改成靜態多頁或 prerender 時 |
| ADR-011 | 產品名 CoffeePath；GitHub repo `coffee-path`；網站 `coffeepath.cjhang.com` | 品牌與工程命名各遵循慣例；網址易輸入且可自訂 | 品牌／商標調查或使用者測試要求改名時 |

## 尚待使用者決策，但不阻擋 M1

1. **視覺語言**：建議溫暖奶白、咖啡棕、鼠尾草綠為主，微量銅色點綴；勿做厚重科技感全黑介面。配色、字型與動畫需先做 2–3 個輕量 prototype 對照。
2. **品牌名稱已決定**：CoffeePath。除非專案擁有者再次要求，不把品牌當成未定案項目；入口文案暫用「從三種原料，看懂咖啡的世界」。已知有相近領域同名網站，正式公開前應自行做臺灣及目標市場商標／品牌查核（詳 docs/07）。
3. **授權**：程式碼建議 MIT、原創內容建議 CC BY 4.0，但正式發布前由專案擁有者確認；第三方函式庫依原授權。
4. **首版核心咖啡名單**：從 15–20 張開始，先人工檢查資料與來源。資料不足寧可少，不要以 164 為硬性 KPI。
5. **正式發佈權限**：已選定 GitHub Repository 名稱 `coffee-path`、Cloudflare Pages 專案建議名稱 `coffee-path`、子網域 `coffeepath.cjhang.com`，但實際建立 repo、Pages 專案、DNS 仍由擁有者授權與確認；不讓 Codex 假定已有操作權限。
6. **3D 是否預設啟用**：第一版先用 2D，完成原型與手機實測後決定。

## 風險與措施

| 風險 | 後果 | 預防與降級 |
|---|---|---|
| 咖啡名稱不具有全球標準 | 使用者被硬分界誤導 | 相近風格、多結果、來源、區間說明 |
| 3D 造成低階手機卡頓 | 流失使用者 | 懶載入、DPR 上限、2D fallback |
| 知識過量 | 中途放棄 | 每關一概念、三層說明、先操作後理論 |
| 點數機制變成壓力 | 失去探索樂趣 | 不扣分、不限重試、熟手入口 |
| localStorage 遭清除 | 進度遺失 | 清楚告知；V1.1 增加匯出匯入 |
| 外部 CDN 或素材變動 | 網頁失效／授權問題 | 依賴自託管、固定版本、保留授權 |
| 文件與程式碼分歧 | 維護困難 | Codex 每一階段更新 README、docs、回歸測試 |
| JSON 與別名失控 | 圖鑑分類灌水 | schema 校驗、穩定 ID、審查 gate |
