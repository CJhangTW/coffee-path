# 09｜教學主線審閱紀錄

日期：2026-11-15。狀態：**審閱建議，尚未改寫既有規格或實作**。

## 審閱目的

從初學者的需求重新檢視旅程：先看見咖啡世界的範圍，再透過容易辨認的例子掌握「咖啡如何形成、加水與加奶有什麼改變」，最後才擴展到作法、名稱與例外。本紀錄是設計假設，不宣稱已完成使用者研究或代表所有台灣使用者。

## 發現與影響

1. **課程入口不夠直覺。** `docs/01` 將「理解少數變數」列為核心承諾，但牛奶章依序從 Espresso Macchiato、Cortado 開始，拿鐵與卡布奇諾反而較晚出現。現有實作亦如此。熟悉的拿鐵可作為加奶入門示例；較陌生的名稱更適合在已有概念後比較。
2. **教學主線容易被品名牽引。** 水章在美式後立刻進入 Lungo；這有助理解萃取與稀釋，但它相對深入。應先讓初學者看到 Espresso、加水、加奶三條關係，再回來比較長萃；此為建議順序，尚需實測。
3. **固定關卡模板和目前互動有落差。** `docs/01` 指定「好奇→預測→操作→回饋→解釋→判斷」，但現有多數關卡主要是操作後答題，尚未完整體現預測、逐步引導及章節回顧。不是每一關都必須增加表單，而應明確設計學習者如何作出預測與觀察差異。
4. **畫面有動畫不代表概念足夠清楚。** 例如卡布奇諾需要讓人理解 Espresso、液態牛奶與奶泡的關係；不可只換顏色或用一團奶泡代替完整組成。2D、3D、減少動態都需要說明相同的起點、過程與結果，不把示例比例說成國際標準。
5. **驗收重點與產品承諾不完全一致。** `docs/01` 和 `docs/04` 的新手指標偏向 Lungo／Americano 與冷萃／急冷；建議增加「解釋 Espresso、加水、加奶的關係」與「比較拿鐵和卡布奇諾的示例」等檢驗。既有進階比較仍有價值，不需刪除。
6. **分期文件存在過期敘述。** `docs/05` 和 `docs/04` 有 M1 不做 3D／先完成 M1 才做 3D 的舊文字；`docs/06` ADR-012、README 與專案實際守則記錄使用者已決定提前試作 3D。後續同步規格時應保留此決策及固定鏡頭、局部動態、2D 降級要求。
7. **知識面仍需審核。** 咖啡命名與奶泡做法會因地區、店家而異；拿鐵和卡布奇諾的比較應說明示例的奶泡質地與比例，避免宣稱單一硬性配方，來源待正式內容審核。

## 建議的學習順序（討論稿）

| 次序 | 學習者要理解的問題 | 熟悉示例及互動重點 |
|---|---|---|
| 1 | 咖啡世界有哪些分支？ | 以咖啡豆、水、牛奶和多個品項呈現全貌，標明哪些路徑尚在開發。 |
| 2 | 濃縮咖啡怎麼來？ | Espresso：水經過咖啡粉床，咖啡液進杯。 |
| 3 | 加水後有什麼改變？ | Americano：先萃取，再加水；與原本的 Espresso 對照。 |
| 4 | 加入牛奶後會如何？ | Latte：在已萃取的 Espresso 加入牛奶，建立牛奶咖啡的基本概念。 |
| 5 | 同樣有牛奶，差別在哪？ | 以 Cappuccino 和前一關示例對照奶泡；清楚區分液態奶與奶泡，說明做法不唯一。 |
| 6 | 改變萃取與改變成品有何不同？ | Lungo vs Americano：分清延長萃取與萃取後加水。 |
| 7 | 牛奶的量與表現如何改變飲品？ | 再引入 Macchiato、Cortado、Flat White，以及不同名稱重疊的情況。 |
| 8 | 溫度、萃取方法及文化怎麼影響分類？ | 冰拿鐵、冷萃／急冷、浸泡／濾泡，再延伸到其他方法與名稱。 |
| 9 | 能否運用概念？ | 用幾個熟悉的情境解釋選擇與變化，再按需延伸進階案例。 |

這是概念順序，不是已核定的關卡數或完整教材；每一關仍需定義先備知識、操作、觀察、正確答案與可接受的例外。是否把進階內容放在主線後段或設為延伸，尚待設計決定。

## 變更前必須處理

- **穩定 ID：**已發行的 `milk-01`／`milk-02` 已與 Macchiato／Cortado 及其獎勵綁定，不應將相同 ID 直接改成不同課程。重排與新增應保留既有完成紀錄、收藏、豆點與深連結；任何資料遷移需明確設計與測試。
- **獎勵：**目前牛奶章獎勵要求五個 ID 全部完成；若調整章節數量或分支，須先決定舊成就如何保留、新成就何時發放，不能因重排而倒扣或重複發獎。
- **同步文件：**核定教學順序後更新 `docs/01`、資料契約、驗收案例、分期文件與 README，再修改程式；不要讓同一 ID 在不同文件指向不同概念。
- **驗證教學，不只驗證功能：**每關先列出「學習者完成後能說出什麼」和可見的操作前／中／後狀態；以自動化測試保障流程、獎勵及舊進度，並手動檢查 2D、3D、減少動態及手機畫面。另安排初學者觀察，尚未進行，不得宣稱已驗證學習成效。
- **分工：**由主負責者先定義概念、限制與驗收；執行者依可檢驗任務實作，交付後由主負責者獨立核對教學、視覺和測試。模型分工可能節省資源，但不保證品質或成本；正確與否取決於任務定義及實際審查。
