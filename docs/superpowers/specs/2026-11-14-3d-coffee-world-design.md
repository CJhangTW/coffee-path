# CoffeePath 3D 咖啡探索桌面設計

## 目的與範圍

以立體探索桌面先表達咖啡世界的範圍，再在現有課程與基本 Lab 中聚焦杯子與水量，幫助初學者看到原料、製程與飲品的關係。這是使用者確認的方向，將原本 M3.5 的 3D 原型提前；不擴張既有課程功能或宣稱已完成未實作的章節。

## 方案

- 採用：首頁顯示簡約 3D 探索桌面，表達咖啡豆、水、牛奶與多種咖啡路徑；關卡及 Lab 使用相同視覺語言，聚焦可隨操作變化的杯子。關卡操作仍以語意化 HTML 控制。
- 單杯方案：較容易實作，但首頁較難傳達學習範圍。
- 完整咖啡館：空間氛圍更豐富，但與本次要驗證的內容關係相比成本較高，留作未來獨立評估。

## 使用者體驗

首頁以 Three.js 呈現溫暖、簡潔、程序化的桌面場景：咖啡豆、水、牛奶和代表不同咖啡路徑的杯子或沖煮器具。場景為概念展示，不把尚未實作的手沖、冷萃章節表現成已開放；HTML 文字明確說明目前提供前三關、基本 Espresso 加水 Lab 與六張可閱讀的咖啡卡。既有兩個主要入口保留，文字與按鈕可於 3D 無法使用時正常操作。

關卡 `water-01`、`water-02` 和 Lab 以 3D 咖啡杯呈現操作前後與加水變化，使用者輸入與既有文字說明保持同步；示意不宣稱精確流體或真實濃度。序章可使用概念場景。滑桿與輸入欄位的互動仍可用鍵盤完成。動畫應短且可減少，不能遮擋閱讀、操作或獎勵。

## 架構與失敗處理

- 沿用純 HTML、CSS、Vanilla ES Modules；Three.js 固定版本自行託管於 `site/vendor/three/` 並保留授權，不使用 CDN、外部模型、圖片或建置工具。版本與來源應記入文件。
- 原先規格禁止首頁預載 Three.js；本次需求提前要求首頁 3D，因此首頁主內容及 2D 預設先可見，再以動態 import 非阻塞載入場景；一般導覽與資料不依賴 3D。
- 共用 renderer 介面管理載入、更新與銷毀；路由切換、非同步載入競態和 WebGL context lost 均需處理。失敗時顯示既有 2D 示意，無需重整或影響課程與進度；允許使用者切回 2D。
- 設定裝置像素比例上限、處理容器縮放，避免長時間無意義動畫；尊重 `prefers-reduced-motion`。渲染器、幾何體、材質、監聽器及 observer 退出時清理。
- 進度與配方規則維持 domain 純函式；穩定 ID、儲存 key、豆點與既有資料不變。

## 驗證

現有原生瀏覽器測試必須通過。新增測試至少覆蓋 3D 載入失敗退回 2D、路由切換時避免過期載入、畫面更新不影響關卡通關或豆點；檢查首頁兩入口、關卡與 Lab 的 3D 及 2D、鍵盤操作、320 CSS px 視窗與減少動態偏好。若無手機實機、iOS 或 GPU 故障環境，明確記為未測，不能將桌面模擬視為實機驗收。
