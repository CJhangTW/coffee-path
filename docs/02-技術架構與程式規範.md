# 02｜技術架構、目錄規劃與程式規範

## 1. 不可突破的技術約束

1. 正式產品是 **Cloudflare Pages 純靜態網站**。禁止建立後端 API、資料庫、Pages Functions、Workers、Serverless、登入與任何按請求計費的服務。
2. 前端只使用 **原生 HTML、CSS、Vanilla JavaScript ES Modules**；Three.js 是唯一允許的圖形函式庫，且按需載入。不得使用 React/Vue/Svelte、Vite/Webpack/Parcel 或運行時 CDN。
3. 正式部署不需 npm install 或 build；只將 `site/` 的原始檔案發布到 Pages。
4. 不使用圖片、影片、外部字型、3D 模型與聲音資產；需要的圖解由 SVG、CSS 或程式化幾何產生。
5. 首頁可無 WebGL 正常完成操作；Three.js 只能是 progressive enhancement。
6. 所有必要教學文字放在語意化 HTML 中，不把 canvas 當文字排版層。

### 2.1 靜態檔案導向

- `site/index.html` 只存應用容器、可見的載入／失敗 fallback、import map、module 入口、meta 與語意化基本區塊；初始 `<title>` 必須是 `CoffeePath`。
- `site/js/config/site-config.js` 集中定義 `brandName: "CoffeePath"`、`repositorySlug: "coffee-path"`、`productionOrigin: "https://coffeepath.cjhang.com"`、`storageKey: "coffeepath.progress.v1"`、產品標語等設定；不要散落硬編碼於 features。
- 相對路徑載入 `site/data`、hash route、history 操作與預覽站 URL 均不得依賴正式網域；SEO canonical 另以 productionOrigin 建立。
- `site/css/*` 不使用 CSS-in-JS；色彩、間距以 CSS custom properties 管理；支援手機、桌機、暗色／高對比（初版至少可讀）。
- `site/data/*` 是公開靜態教材，不包含帳密、Token 或私密資料。
- `site/js/domain/*` 不得 `document.querySelector()`、不得 import Three.js、不得讀 localStorage；必須可單獨測試。
- `site/js/features/*` 只負責頁面呈現與使用者事件，不在 HTML 樣板中塞數百行配方規則。
- `site/js/core/storage.js` 不能直接滲透至 domain；以參數／回傳值交換資料。
- 不允許大量巨型模組；超過約 300 行時應檢查是否有可分割的獨立責任，並不是強制字數限制。

## 3. 狀態與資料流

```text
使用者事件 (DOM)
    │
    ▼
features controller ──────────────┐
    │                              │
    ▼                              ▼
pure domain function         content-loader
    │                              │
    ▼                              ▼
store reducer / action        static JSON
    │                              │
    ├───────────────┬──────────────┘
    ▼               ▼
HTML / SVG      optional 3D renderer
    │
    ▼
localStorage adapter （僅進度／偏好）
```

- 非同步載入資料採 `AbortController`（路由切換時取消不必要下載），避免重複請求與競態。
- 使用 `location.hash` 進行導航，例 `#/journey/water-02`、`#/lab`、`#/atlas/cortado`、`#/map`；支援上一頁、下一頁及重新整理深連結。
- 深連結對應的 JSON 並未成功載入時，給清楚錯誤訊息與「重試」操作。
- 原生 JavaScript function 與 JSDoc 作型別註記；不需要 TypeScript 編譯，必要時可使用 `// @ts-check` 靜態檢查，但不引入運行時框架。
- 必要的互動按鈕請使用 `<button>`；表單輸入使用 `<label>`；不要以 canvas 點選作唯一操作方法。

## 4. 畫面切分與視覺表現

- 首頁：「三原料」主視覺 + 兩種入口 + 簡短賣點。
- Journey：上方章節／進度，下方一段操作指示；中央是 2D 可讀杯型示意；側邊／抽屜顯示解說。
- Lab：控制項、杯型、相近風格結果、差異提示與比較按鈕；桌機 2–3 欄，手機上下排。
- Atlas：全文搜尋，家族過濾，標籤及卡片；不強制載入 3D。
- Map：2D 節點圖；不使用大量同時運轉的 3D 節點。
- 元件設計：提供 DOM 自身 focus、aria-label、說明文字，不只靠顏色或動畫傳訊。
- 請使用可產生正確概念的 SVG 杯量示意；3D 液面與混合色只作視覺輔助，需有「示意圖，非實際物理模擬」標示。

## 5. Three.js 的隔離與載入

- 原生 `importmap` 指向同源固定版本，例如 `./vendor/three/build/three.module.js`，addons 指向同版本 `./vendor/three/examples/jsm/`。保留上游所有必要模組與授權，不能僅複製主入口而遺漏 `three.core.js` 等相依。
- `renderer-factory.js` 對 `coffee3d.js` 執行 `import()`，**首頁不可有靜態 import 將 Three.js 整包載入**。
- 開啟 3D 的條件：使用者啟用且瀏覽器可用 WebGL；故障時切回 2D，不得造成頁面崩潰。
- 避免無條件 perpetual `requestAnimationFrame`；只在值變化／正在播放有效動畫時更新。
- 背景分頁停止渲染，元件離開 viewport 後停止；使用 `IntersectionObserver`／`visibilitychange` 可達成。
- 控制繪圖解析度、draw calls、幾何數；不要每滴水都建立獨立 Mesh，優先程序化剖面、共用材質。
- 依 `prefers-reduced-motion: reduce` 取消非必要動態；開關支援手動切換。
- 不可依賴外部圖片、3D 模型、線上 CDN 或字型；預設使用系統字型。

## 6. 可維護性與變更規則

1. 一個領域概念只寫在一個資料來源或 pure function，不在各頁複製條件式。
2. 每次變更規則引擎、點數或資料 schema，必須補或修正對應測試。
3. JSON `id`、`lessonId`、`drinkId` 一旦發布即視為持久契約；變更需 migration 或 alias map。
4. UI 元件不讀寫原始 `localStorage`；統一透過 storage adapter。
5. 內容必須有來源 ID、可信程度，並標記是否傳統配方、改製或實驗性飲品。
6. 不把地域別名、器具、萃取方法全部當作獨立咖啡數量相加。
7. 不使用 `innerHTML` 插入使用者可輸入內容或未審查字串；優先 `textContent` 與 DOM API。
8. 簡單的場景以 DOM、CSS、SVG 呈現；新增 3D 前應說明 2D 為何不足。
9. 如欲新增任何依賴，須先列出用途、體積、維護與授權理由；不應默默加入框架。
10. 所有對外功能名稱、知識說明與 UX 文字預設臺灣繁體中文，並保留英文飲品名稱。

## 7. 開發環境與發行

- 啟動：進入專案 `site/` 後執行 `python -m http.server 8000`，以 `http://localhost:8000` 開啟。
- 測試：以另一個靜態 server 根目錄掛載專案並開啟 `/tests/index.html`，或直接以原生瀏覽器測試器將案例放於 `site/tests/` 的開發副本。測試流程應記載在 README，避免測試檔被意外部署。
- Cloudflare Pages：Framework = None；Build command = `exit 0`；Build output directory = `site`；無 environment secrets。
- GitHub：Repository `coffee-path`、預設 `main` 分支部署正式站，PR 產生預覽；提交前人工驗收中文教材與 2D fallback。
- Repository About：名稱與中文標題保留 `CoffeePath`，GitHub slug 使用全小寫 `coffee-path`；不使用品牌 PascalCase 當 repo slug。
- Pages Project：建議 `coffee-path`，若 `coffee-path.pages.dev` 已被占用，可調整 Pages 專案名，不改變 repo slug 與正式網域。
- 自訂域名：Pages > Custom domains 增加 `coffeepath.cjhang.com`，再處理自動或手動 CNAME，**不可只設 DNS 而忽略 Pages 綁定**。

## 8. 成本與版本紀律

- 只要沒有觸發 Functions，Cloudflare Pages 的純靜態資產請求目前免費且不限次數；仍受免費方案建置次數、檔案數等配額限制。
- 伺服器成本不代表「所有成本為零」：網域續費、維護、使用者流量與裝置電力仍存在。
- Three.js 固定版本，升級另開 PR 並做全部瀏覽器測試。
- 不發布任何含有 API 金鑰、Token、公司內網資源或個資的內容。

## 9. 程式命名約定

- Repo／目錄／一般檔案：`kebab-case`（例 `coffee-path`, `lesson-engine.js`）。
- JS 函式與變數：`camelCase`；類別與型別／建構子：`PascalCase`；固定常數：`UPPER_SNAKE_CASE`（視上下文）。
- CSS class：`kebab-case`；CSS custom properties：`--coffee-...` 或 `--color-...`，整站一致即可。
- JSON IDs／URL 路由：穩定 `kebab-case`；資料欄位：`camelCase`；品牌顯示文字固定 `CoffeePath`。
- 分支可使用 `feat/lesson-water`、`fix/progress-storage`、`docs/deploy-pages`；commit 採 `feat: ...`、`fix: ...`、`docs: ...` 方便維護，但不需要安裝 commitlint。
- 內容需有 README、AGENTS、來源資訊及測試，避免程式命名與品牌混淆。
